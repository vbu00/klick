# kl!ck — для разработчиков

Как устроены исходники, как собрать и проверить kl!ck. Описание для пользователей — в [README](../README.md).

## Состав

| Папка | Что это |
|---|---|
| `crates/klick-core` | Логика без Windows: модель настроек, сборка конфига mihomo, страж связи, разбор подписок. Покрыта тестами |
| `crates/klick-proto` | Канал управления: сообщения между окном и службой, одна строка JSON на сообщение |
| `crates/klick-service` | Служба: ядро (объект задания Windows), API ядра через именованный канал, подписки, Kill Switch (WFP), проверка IP, соседи, смена сети, служба Windows |
| `crates/klick-cli` | Утилита для проверки службы без окна |
| `crates/klick-ui` | Окно на Tauri 2: мост к службе через канал управления, значок в трее (exe называется `klick.exe`) |
| `crates/klick-setup` | Установщик на Tauri 2: ставит, обновляет, переустанавливает и удаляет kl!ck, убирает прежнюю kl!ck 0.2–0.3. Программа вшита в exe |
| `ui` | Интерфейс окна и установщика (`setup.html`): React + Vite + TypeScript, по макетам Димы |
| `resources` | Ядро mihomo 1.19.31, база стран, стартовые наборы, каталог сервисов |
| `sandbox` | Автоматическая проверка в Песочнице Windows |

## Сборка

```
cargo test
cargo build
```

Библиотека C вшита в exe (`.cargo/config.toml`), отдельный Visual C++ Redistributable не нужен.

Ядра и базы стран в git нет: `build.ps1` скачивает их сам в `resources/core` (`tools/fetch-core.ps1` — официальный релиз mihomo и country.mmdb с проверкой sha256). Это те же файлы, что в kl!ck 0.3.0:

| Файл | SHA-256 |
|---|---|
| `mihomo.exe` (v1.19.31, windows amd64, with_gvisor) | `1fa8055e03596fc35167f70e9ecd1890517d38d960a39177445746a1b0defc2b` |
| `Country.mmdb` | `21606dfffd4ec39542ec40782bebd37b71310471816e1338b6f6430190cbc85d` |

Нужны Rust (stable, MSVC) и Node.js 20.19+ или 22.12+ (для Vite 8); перед первой сборкой — `npm install` в `ui`.

Готовый установщик — одной командой: страницы, окно, служба, затем `klick-setup.exe` с программой внутри.

```
powershell -ExecutionPolicy Bypass -File build.ps1          # dist\klick-setup.exe (release)
powershell -ExecutionPolicy Bypass -File build.ps1 -Debug   # то же в отладочной сборке
```

## Установщик

`klick-setup.exe` просит права администратора один раз. Если kl!ck не стоит — мастер установки, если стоит — «Обновить / Переустановить / Удалить». Прежнюю kl!ck (0.2–0.3, папка `Program Files\kl!ck`) находит сам и удаляет со всеми следами. Копия установщика остаётся в папке программы: ею kl!ck удаляется из «Установленных приложений».

Без окна (для администраторов и проверок), код выхода 0 — готово, 1 — ошибка:

```
klick-setup.exe --silent [--path <папка>] [--no-desktop] [--no-autostart]
klick-setup.exe --silent --uninstall [--wipe]
```

Экраны установщика в браузере — с подставными данными: `http://127.0.0.1:5173/setup.html?s=old` (есть прежняя kl!ck), `?s=maintain`, `?s=same`, `?s=newer`, `?s=uninstall`, `?s=fail`.

Проверка — в Песочнице (`sandbox\start.ps1 -Release -Setup`), см. ниже. На рабочем компьютере установщик сразу убирает прежнюю kl!ck вместе с её настройками (подписки добавляются заново).

## Служба для разработки

Не трогает систему: свой канал `\\.\pipe\klick-dev`, порт 17890, без TUN и без брандмауэра, данные в `.dev-data`.

```
target\debug\klick-service.exe console
target\debug\klick-cli.exe status
target\debug\klick-cli.exe add <ссылка на подписку или vless://…>
target\debug\klick-cli.exe servers
target\debug\klick-cli.exe latency
target\debug\klick-cli.exe connect
target\debug\klick-cli.exe ip
target\debug\klick-cli.exe watch
```

Остальные команды: `klick-cli --help`. `.dev-data` содержит ключи серверов — в передаваемые исходники не входит (см. `.gitignore`).

## Окно

```
cd ui
npm install
npm run dev          # превью в браузере с тестовой службой: http://127.0.0.1:5173/?s=connected
npx vite build       # сборка страницы для окна
cd ..
cargo build -p klick-ui
```

В браузере окно работает с тестовой службой (`ui/src/lib/mock.ts`): под окном переключатель состояний — нет подключений, выключен, подключён, переподключение, сервер не отвечает, ошибка, мешает zapret. Окно трея — `?view=tray` (например `http://127.0.0.1:5173/?view=tray&s=connected`), светлая тема — `&theme=light`. В Tauri окно говорит с настоящей службой через `\\.\pipe\klick`; со службой для разработки — если запустить с переменной `KLICK_DEV=1`.

Настоящим окном можно управлять из скрипта: с переменной `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9341` WebView2 открывает порт отладки (протокол Chrome DevTools) — так проверялись шаги окна без мыши. В рабочей сборке переменную не задавать.

## Проверка в Песочнице

TUN, Kill Switch, служба и падения проверяются в Песочнице Windows:

```
powershell -File sandbox\start.ps1
```

Скрипт собирает папку с программой, открывает Песочницу и ждёт отчёт. Внутри `sandbox\run.ps1` ставит службу, поднимает тестовый «VPN-сервер» (второй mihomo с socks5), проходит сценарии и выключает Песочницу. Ключи настоящих серверов не нужны.

Установщик — там же:

```
powershell -File sandbox\start.ps1 -Release -Setup
```

`sandbox\setup-test.ps1` ставит в Песочницу прежнюю kl!ck 0.2 (файлы программы с этого компьютера, без данных пользователя) со всеми её следами, ставит поверх `klick-setup.exe`, прогоняет на установленной копии все проверки `run.ps1`, переустанавливает (с занятой папкой — проверка отката — и без), удаляет копией из папки программы, ставит в свою папку без ярлыков и удаляет вместе с данными.

Kill Switch и браузер — отдельным сценарием:

```
powershell -File sandbox\start.ps1 -Release -Script ks-browser
```

`sandbox\ks-browser.ps1` ставит kl!ck установщиком, кладёт Edge (движок Chrome) в Kill Switch, включает режим «Системный прокси» и через протокол отладки открывает страницы в одном и том же, всё время работающем Edge, пока VPN много раз включается и выключается, в том числе с переходом TUN → прокси на ходу. Рядом пишется, что видит Windows: значения реестра, запись `DefaultConnectionSettings` (её читает браузер) и .NET. Отчёт — `results\ks-browser.txt`.

## Готово

- Сборка конфига: лестница правил (внутри списка точное правило раньше общего), два положения тумблера со своими списками, переключатели «.ru и .рф напрямую» и «Российские IP напрямую», Kill Switch по папкам программ, DNS с подменными адресами, служебные входы «через VPN» и «напрямую». Все варианты проверены `mihomo -t`.
- Ядро: запуск, ожидание готовности, остановка, перезапуск при падении (до 3 раз), завершение вместе со службой.
- Подключения: подписка, одиночная ссылка, файл; ссылки зашифрованы DPAPI; автообновление подписок (как просит панель, иначе раз в 12 ч); предупреждения о конце срока и трафика.
- Страж: проверка раз в 30 с, попытки через 2, 5, 8 с, «сервер не отвечает» на 15-й, тихая проверка раз в минуту; «следующий рабочий» и «самый быстрый»; проверка сразу после смены сети и пробуждения.
- Проверочное ядро для списка серверов и задержки при выключенном VPN.
- Kill Switch в WFP: через туннель можно, внутри компьютера и в локальной сети можно, остальное нельзя; держится без службы и после перезагрузки.
- «Как вас видят сайты» (через VPN и напрямую, утечки IPv6 и DNS), «Сейчас в сети», «Не открывается?», поиск соседей (zapret, GoodbyeDPI, WinDivert, другие VPN).
- Служба Windows: установка, удаление, перезапуск при сбое, возврат VPN после сбоя службы; папка данных закрыта от обычных пользователей; журнал без адресов сайтов.

- Окно, шаг 1: рамка по макету (заголовок, нижняя панель, тема «Графит»), главная с живыми данными службы (статус, кнопка, чип режима, подключения, серверы, скорость и график, состояния переподключения и ошибок, лист «Сменить подключение?» со схемой), «Добавить» (ссылка и файл), значок в трее, крестик сворачивает в трей.
- Окно, шаг 2: «Соединение» по макету v4 — режим и лист «Как работает режим», «Куда направлять», готовые правила («Заблокированное в РФ — через VPN» и переключатели России), карточка «Мой список», сводка «Сейчас в сети», «Не открывается?», живая схема по реальным соединениям, «Как вас видят сайты»; экраны «Мой список» (вкладки, правило включается и выключается без удаления, удаление с отменой), «Сейчас в сети» (Live / пауза, по программам и по сайтам, тумблер «через VPN» пишет правило в мой список) и «Не открывается?»; лист «Добавить в «…»»: сервисы из каталога, программы из «Запущены сейчас» и «Выбрать .exe…», сайты и IP.
- Служба: каталог сервисов и «Запущено сейчас» (владельцы открытых сокетов, названия из свойств exe); правило программы встаёт на папку установки — папки версий и версии пакетов Microsoft Store пропускаются, общие папки вроде «Загрузок» не принимаются.

- Окно, шаг 3: «Настройки» — Kill Switch (свой переключатель у каждой программы, выбор из «Запущено сейчас» и «Обзор…», пометка «не найдена», лист «Как работает Kill Switch»), «Если сервер недоступен», «Восстанавливать подключение», тема (системная, светлая, тёмная, своя: основа и акцент), «Запускать с Windows», «Обновлять подписки», «Уведомлять об обрывах», порт прокси, журнал, «Скопировать отчёт», «О приложении» с проверкой обновлений.
- Служба: журнал в памяти для окна, отчёт, версия ядра и системы, проверка выпусков на GitHub, названия программ по папкам (описание главного exe), возврат VPN после входа в Windows, Kill Switch замечает обновление программы в новую папку и пропавшие программы. Из строк ядра в журнале и отчёте вычищаются адреса сайтов и серверов.

- Служба: правило в списке можно выключить, не удаляя (`list toggle` в `klick-cli`); набор «Заблокированное в РФ» выключается (`prefs --blocked off`) — тогда через VPN идёт только свой список.
- Окно, шаг 4: окно трея по макету Tray v2 (кнопка со статусом и временем, «Вставить из буфера», скорость, доля VPN, тумблер, «Открыто сейчас», профили, серверы, Kill Switch, короткие настройки, «Открыть», «Выход»; высота по содержимому, цвета — тема приложения), значок трея по состоянию (иконки Димы, размер под масштаб экрана), окно фиксированного размера без «развернуть», в заголовке — значок цвета состояния и название kl!ck, выход с выбором «отключить VPN / оставить работать» и «Запомнить выбор», уведомления Windows с переходом на нужный экран, системный прокси (окно ставит и снимает его через WinINet одной операцией — браузеры сразу видят новую запись настроек, на время VPN выключается «Определять параметры автоматически»; прежние настройки возвращаются целиком; без окна прокси ставит и снимает служба; чужой прокси не трогается).

- Установщик: мастер по макету (приветствие, параметры, установка с задачами и «Отменой» до необратимых шагов, готово), «уже установлено» (обновить / переустановить / удалить), удаление с галочкой данных, экран ошибки с откатом. Ставит в Program Files или свою папку (права как у Program Files), регистрирует службу, ярлык в «Пуске» с AppUserModelID `app.klick.desktop` (уведомления от имени kl!ck), ярлык на рабочем столе и автозапуск по выбору, запись в «Установленных приложениях». Удаляет прежнюю kl!ck 0.2–0.3 со всеми следами (её деинсталлятор, процессы, задача, правила брандмауэра, прокси, ярлыки, настройки, реестр, значок трея, уведомления; соседние программы автора не трогает). Удаление убирает службу, фильтры Kill Switch, свой прокси, драйвер Wintun (если им не пользуется другой VPN), ярлыки, автозапуск и файлы. Тексты лицензий — в `resources\licenses`.

## Сделано отдельными коммитами

По одному коммиту на тему, с тестами:

- **Замер задержки напрямую.** Проверочное ядро — тот же `mihomo.exe`; в TUN его соединения шли в туннель основного, и задержка «другого» подключения мерилась через текущий сервер. Первое правило — `PROCESS-PATH-REGEX` по точному пути ядра → `DIRECT`.
- **DNS Яндекса по DoT.** `https://77.88.8.8/dns-query` не отвечает (пустой ответ) — стало `tls://77.88.8.8:853`; для адресов серверов добавлен запасной UDP.
- **IPv6 без зависаний.** С `ipv6: true` браузер со своим DoH шёл на IPv6-адрес сайта, и на сервере без IPv6 страница висла. Сниффер TLS/QUIC подменяет адрес на имя сайта — сервер находит сайт сам; утечки мимо туннеля нет.
- **Системный прокси не остаётся после выключения компьютера.** Окно возвращает прокси по `WM_ENDSESSION`; служба больше не стирает отметку, если снять прокси не смогла (никто ещё не вошёл), и пробует снова после входа.
- **Канал управления проверяется.** Окно отдаёт команды, только если на том конце — служба от имени системы (`klick-service.exe`); занявшая имя чужая программа ничего не получает.
- **Установщик.** Нет экрана «Параметры» — папка и переключатели на первом экране. Подписки прежней kl!ck 0.2–0.4 переносятся (переключатель «Перенести подписки»); при обновлении и переустановке — «Начать с чистого листа». WebView2 Runtime ставится сам, если его нет (загрузчик Microsoft с проверкой подписи).
- **Окно** нельзя развернуть двойным щелчком и Win+↑; высота подгоняется заново при переходе на экран с другим масштабом.
- **Значки** — крупные клавиши kl!ck: подключено, подключаюсь (синий), сервер не отвечает, ошибка, выключено (серый).
- **Названия положений:** «VPN для всего» и «VPN для выбранного».
- **Набор «Заблокированное в РФ»** дополнен общим списком itdoginfo/allow-domains (~1200 доменов): ядро качает его само через VPN раз в сутки; не скачался — работает встроенный.
- **Песочница:** `run.ps1` ставит WebView2 сам (в образе Песочницы его бывает нет) и не путает проверку связи ядра с обычным сайтом; новый сценарий `ui-check` — установщик с переносом подписок, снимки окна и трея, «Развернуть», чужой канал.

## Дальше
- **Поправить:** сейчас, если у программы есть своё правило или она в Kill Switch, тумблеры её сайтов в «Сейчас в сети» серые. В макете v4 сайты под программой переключаются по одному. Предлагаемый порядок: Kill Switch → сайты, сервисы и IP → программы → готовые наборы → остальное. Сайты программы из Kill Switch напрямую не пустить: WFP заблокирует. Где менять: блокировка тумблеров и порядок в интерфейсе — `groupLive` и `decide` в `ui/src/lib/live.ts`, порядок правил для ядра — `crates/klick-core/src/compile.rs`.
- Английский перевод интерфейса и установщика (тексты собраны в `ui/src/lib/i18n.ts`, экранах и `ui/src/setup/texts.ts`).
- Проверка на ПК Димы с настоящим сервером: установщик сам уберёт старую kl!ck.
- Сборка наборов из открытых списков сообщества.
